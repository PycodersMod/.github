# Contributing to PycodersMod

Thanks for helping improve PycodersMod projects.

## Workflow

1. Open an issue to discuss a substantial change or compatibility target.
2. Fork the repository and create a focused branch.
3. Keep changes limited to one repository and follow that repository's build and test instructions.
4. Open a pull request against `main`, describe the user-visible effect, and include the relevant build or test result.
5. Address review feedback and wait for an approval from the repository code owner before merge.

Direct updates to `main` are restricted by repository rules. Do not include machine-specific paths, private account details, credentials, local proxy configuration, or unredacted local logs in issues, commits, pull requests, or artifacts.

## Mod repository layout

Mod source lives below `<loader>/<minecraft-version>/`, for example `forge/1.20.1/` or `fabric/1.21.6/`. Repository metadata such as `README.md`, `LICENSE`, `CODEOWNERS`, and `.gitignore` remains at the repository root. See [Mod repository layout](docs/MOD_REPOSITORY_LAYOUT.md).
